# Al Brooks Dubbed — راهنمای فارسی

> English version: [README.md](README.md)

این پروژه یک خط لوله (pipeline) محلی و **بدون نیاز به GPU** است که یک ویدیوی
سخنرانی انگلیسی را به یک قطعه‌ی ۳۰ ثانیه‌ای قابل پخش و یک متن انگلیسی دقیق
همراه با زمان‌بندی تبدیل می‌کند. این کار پایه‌ی مراحل بعدیِ دوبله (dubbing)
فارسی است.

## دامنه

### فاز ۱ — برش ویدیو و رونویسی انگلیسی ✅

1. **برش ویدیو** — استخراج نخستین *N* ثانیه (پیش‌فرض ۳۰ ثانیه) با FFmpeg.
2. **رونویسی انگلیسی** — ارسال صدای همان بازه به API گفتار به متن Groq و ذخیرهٔ
   متن به‌صورت UTF-8 و نیز یک فایل JSON ساختاریافته.

### فاز ۲ — بازرسی کیفیت و آماده‌سازی متن ✅

3. **بازرسی کیفیت** — شناسایی بخش‌های تکراری، زمان‌بندی خراب، شکاف، هم‌پوشانی
   و ناهماهنگی متن با بخش‌ها، و گزارش ساختاریافته.
4. **آماده‌سازی** — پاک‌سازی قطعیِ قالب‌بندی به‌همراه JSON آمادهٔ ترجمه که پیوند
   هر بخش با زمان‌بندی اصلی صدا را حفظ می‌کند.
5. **تأیید اختیاری** — رونویسی دوبارهٔ *همان صدا* (به‌درخواست صریح و محدود) که
   تنها با شواهد واقعی اجازهٔ اصلاح می‌دهد.

موارد زیر **هنوز پیاده‌سازی نشده‌اند**: ترجمهٔ فارسی، تولید گفتار (TTS)،
شبیه‌سازی صدا، هماهنگ‌سازی لب، و دوبلهٔ کل ویدیو. جزئیات در
[ROADMAP.md](ROADMAP.md) آمده است.

## اصل کلیدی فاز ۲

**متن مشکوک هرگز به‌طور پنهانی تغییر نمی‌کند.** خروجی فاز ۱ مرجع اصلی است و
فقط خوانده می‌شود. فاز ۲ فایل‌های تازه می‌نویسد و تنها زمانی تکراری را حذف
می‌کند که رونویسی مستقلِ دوبارهٔ همان صدا خلاف آن را اثبات کند. در غیر این
صورت متن عیناً حفظ و برای بررسی انسانی علامت‌گذاری می‌شود.

## راه‌اندازی در ویندوز

### ۱. ساخت محیط مجازی

در ریشه‌ی پروژه اجرا کنید:

```powershell
cd D:\Projects\al-brooks-dubbed
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### ۲. نصب وابستگی‌ها

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

وابستگی‌ها **هرگز به‌صورت سراسری نصب نمی‌شوند**.

### ۳. تنظیم `GROQ_API_KEY`

کلید را از <https://console.groq.com/keys> بسازید و سپس:

```powershell
$env:GROQ_API_KEY = "gsk_..."
```

بررسی وجود متغیر **بدون چاپ کردن مقدار آن**:

```powershell
if ($env:GROQ_API_KEY) { "GROQ_API_KEY is set" } else { "GROQ_API_KEY is missing" }
```

یا کل بررسی محیط:

```powershell
python -m src.main --check-env
```

این دستور نسخه‌ی ffmpeg/ffprobe و وجود کلید را گزارش می‌دهد، اما **هرگز
مقدار کلید را چاپ نمی‌کند**.

> فایل `.env` **اختیاری** است. اگر متغیر ویندوز تنظیم باشد، نیازی به آن نیست.

## اجرا

```powershell
# پردازش خودکار تنها ویدیوی موجود در پوشه data
python -m src.main

# انتخاب صریح فایل ورودی
python -m src.main --input lecture.mp4

# تعیین مدت زمان قطعه‌ی آزمایشی
python -m src.main --input lecture.mp4 --duration 30

# بازنویسی خروجی‌های قبلی
python -m src.main --overwrite

# راهنمای کامل
python -m src.main --help
```

اگر بیش از یک ویدیو در پوشهٔ `data` باشد، برنامه هرگز حدس نمی‌زند؛ فهرست
فایل‌ها را نمایش می‌دهد و از شما انتخاب صریح می‌خواهد.

## فاز ۲ — بازرسی کیفیت و آماده‌سازی

این مرحله روی خروجی فاز ۱ کار می‌کند و **به‌طور پیش‌فرض هیچ درخواستی به API
نمی‌فرستد**.

```powershell
# پاک‌سازی و تحلیل یک متن موجود
python -m src.main --prepare-transcript output\lecture_test_30s.en.json

# بازنویسی خروجی‌های آماده‌شدهٔ قبلی
python -m src.main --prepare-transcript output\lecture_test_30s.en.json --overwrite

# افزون بر آن، رونویسی دوبارهٔ همان صدا برای بررسی بخش تکراری
# (این کار مصرف API دارد)
python -m src.main --prepare-transcript output\lecture_test_30s.en.json --verify-transcript

# تعیین فایل صوتی و تعداد تلاش‌ها
python -m src.main --prepare-transcript output\lecture_test_30s.en.json `
    --verify-transcript --audio output\lecture_test_30s.flac --verify-attempts 2
```

### چگونه متن مشکوک را بررسی کنیم

1. یادداشت‌های **Review needed** در خروجی خط فرمان را بخوانید؛ بخش‌ها و
   بازه‌های زمانی در آن مشخص شده است.
2. ویدیوی برش‌خورده را در همان بازه باز کنید و **گوش کنید**.
3. سپس و در صورت نیاز تصمیم بگیرید.

### نتیجهٔ تأیید

| وضعیت | معنی | کاری انجام می‌شود |
|---|---|---|
| `duplicate_contradicted` | رونویسی دوباره تکرار را ندارد | فقط در این حالت بخش‌ها ادغام می‌شوند |
| `duplicate_confirmed` | رونویسی دوباره همان تکرار را دارد | چیزی حذف نمی‌شود |
| `inconclusive` / `failed` | شواهد قطعی نیست | چیزی حذف نمی‌شود و علامت‌گذاری می‌شود |

> تکرار در گفتار طبیعی است و خودکار خطا تلقی نمی‌شود. عبارت‌های تکراری تنها
> با شدت `low` گزارش می‌شوند و هرگز حذف نمی‌شوند.

## فایل‌های خروجی

برای ورودی `lecture.mp4`:

**فاز ۱ (خام، مرجع اصلی، هرگز تغییر نمی‌کند)**

| فایل | محتوا |
|---|---|
| `output/lecture_test_30s.mp4` | ویدیوی برش‌خورده |
| `output/lecture_test_30s.en.txt` | متن ساده انگلیسی (UTF-8) |
| `output/lecture_test_30s.en.json` | متن ساختاریافته + فراداده |
| `output/lecture_test_30s.metadata.json` | مشخصات رسانه و برش |

**فاز ۲ (مشتق، قابل تولید مجدد)**

| فایل | محتوا |
|---|---|
| `output/lecture_test_30s.en.clean.txt` | متن پاک‌شده و آمادهٔ ترجمه |
| `output/lecture_test_30s.en.clean.json` | بخش‌های آماده، نسخهٔ ۲ |
| `output/lecture_test_30s.qa.json` | یافته‌های ساختاریافتهٔ کیفیت |

خروجی‌های موجود بدون هشدار بازنویسی نمی‌شوند؛ برای این کار `--overwrite`
لازم است.

## واژه‌نامهٔ تخصصی

فایل `src/resources/terminology.json` شامل ۳۵ اصطلاح حوزهٔ Al Brooks است. در
فاز ۲ فقط برای **برچسب‌گذاری** استفاده می‌شود و هرگز متن را تغییر نمی‌دهد.

### اصطلاحات به انگلیسی گفته می‌شوند

تریدرهای فارسی می‌گویند «wedge bull flag»، نه ترجمهٔ تحت‌اللفظی. بنابراین
مدخل، شکل انگلیسی را به‌عنوان شکل گفتاری ثبت می‌کند و این تصمیم را صریح
علامت می‌زند:

```json
{
  "id": "bull_flag",
  "canonical": "bull flag",
  "persian": "bull flag",
  "speak_original": true
}
```

وجود `speak_original` مهم است: بدون آن، یک مقدار انگلیسی داخل فیلدی به نام
`persian` به نظر اشتباه تایپی می‌آید.

**اگر خواستید ترجمه شود:** مقدار `persian` را عوض کنید و پرچم را حذف کنید.

| کلید | کاربرد |
|---|---|
| `terms[].persian` | اصطلاح در فارسی چه گفته می‌شود |
| `terms[].speak_original` | `true` یعنی عمداً همان انگلیسی گفته شود |
| `known_confusions` | اشتباهات رونویسی تأییدشده |
| `confusable_extra_anchors` | جفت‌کلمه‌های لنگر برای تشخیص اشتباه |

### تشخیص اشتباه صوتی-نوشتاری

خطرناک‌ترین خطاهای رونویسی، کلمات نامفهوم نیستند؛ کلمات کاملاً درست با
معنی فنی اشتباه‌اند. در نمونهٔ ۱۰ دقیقه‌ای این سخنرانی:

| نوشتهٔ API | درست | تعداد |
|---|---|---|
| `training range` | `trading range` | ۶ |
| `bare bar` / `bare body` | `bear bar` / `bear body` | ۳ |

اگر اینها اصلاح نشوند، به‌صورت تحت‌اللفظی ترجمه می‌شوند و تریدر فارسی‌زبان
اصطلاحی می‌گیرد که هرگز استفاده نشده است. برنامه آنها را با
`confusable_term` علامت‌گذاری می‌کند و **هرگز متن را تغییر نمی‌دهد**.

برای افزودن موارد جدید، کافی است در همان فایل JSON اضافه کنید:

```json
{
  "wrong": "training",
  "right": "trading",
  "note": "در سخنرانی BTR20140930 شنیده شد."
}
```

## تنظیم پروکسی

در برخی شبکه‌ها (از جمله بسیاری در ایران) ترافیک از یک پروکسی محلی عبور
می‌کند. پاورشل و FFmpeg تنظیمات پروکسی ویندوز را رعایت می‌کنند، اما پایتون
این کار را نمی‌کند و در نتیجه هر درخواست به Groq با خطای
`403 Forbidden` رد می‌شود — حتی اگر کلید کاملاً درست باشد.

برنامه به‌طور خودکار پروکسی ویندوز را تشخیص می‌دهد. برای تنظیم دستی:

```powershell
$env:GROQ_PROXY = "http://127.0.0.1:1080"
```

## اجرای آزمون‌ها

```powershell
.\.venv\Scripts\python.exe -m pytest
```

آزمون‌های واحد **هرگز** API گروک را صدا نمی‌زنند و به کلید واقعی نیاز
ندارند. آزمون‌های یکپارچه یک ویدیوی مصنوعی کوچک با FFmpeg می‌سازند و هیچ
فایل رسانه‌ای در مخزن ذخیره نمی‌شود.

> اگر pytest در پایان اجرا با خطای `PermissionError` متوقف شد، پوشه‌ی موقت
> پیش‌فرض آن قابل نوشتن نیست:
>
> ```powershell
> $env:PYTEST_DEBUG_TEMPROOT = "$PWD\.pytest_tmp"
> New-Item -ItemType Directory -Path .pytest_tmp -Force | Out-Null
> .\.venv\Scripts\python.exe -m pytest
> ```

## رفع اشکال

- **`GROQ_API_KEY is not set`** — متغیر را در همان ترمینالی تنظیم کنید که برنامه را اجرا می‌کنید.
- **`403 Forbidden`** — معمولاً مشکل پروکسی است، نه کلید. `--check-env` را اجرا کنید.
- **`ffmpeg was not found on PATH`** — پوشه‌ی `bin` مربوط به FFmpeg را به `PATH` اضافه کنید یا `FFMPEG_PATH` را تنظیم کنید.
- **چند ویدیو پیدا شد** — با `--input "<نام فایل>"` انتخاب کنید.
- **متن خالی** — آن بازه احتمالاً گفتاری ندارد؛ بازه‌ی دیگری را با `--duration` امتحان کنید.
